Every command accepts `--help` for its full flag list, for example `opencode run --help`. Some server-backed commands accept `--standalone` to run a private server or `--server <url>` to target a specific one; check the command's help for its supported flags.

## run

Sends a message and prints the reply without opening the interactive interface.

```bash
$ opencode run "Explain this repository"
```

### CI

In CI, pass a provider API key as a secret and use standalone mode so the private server receives it. For example, this GitHub Actions job reviews the checked-out repository:

```yaml
name: OpenCode review
on: [pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install --global @opencode/cli
      - run: opencode run --standalone --model anthropic/claude-sonnet-5-5 "Review this repository for correctness and summarize any issues."
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

Choose a model.

```bash
$ opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

Continue the last session.

```bash
$ opencode run --continue "Now handle the expired case"
```

Emit newline-delimited JSON for scripts.

```bash
$ opencode run --format json "List the TODO comments"
```

Attach files to the message.

```bash
$ opencode run --file src/server.ts --file src/client.ts "Review these for bugs"
```

Run with a specific agent.

```bash
$ opencode run --agent build "Fix the failing test"
```

Continue a specific session.

```bash
$ opencode run --session ses_4f2a1c "Check edge cases"
```

Auto-approve permissions that are not explicitly denied.

```bash
$ opencode run --auto "Fix the failing test"
```

View all subcommands and flags.

```bash
$ opencode run --help
```

## session

Manages sessions.

```bash
$ opencode session list
```

Limit the list and print JSON.

```bash
$ opencode session list --max-count 20 --format json
```

Delete a session and its child sessions.

```bash
$ opencode session delete ses_9c1b08
```

Export session data as JSON.

```bash
$ opencode session export ses_4f2a1c
```

Redact sensitive transcript and file data when exporting.

```bash
$ opencode session export ses_4f2a1c --sanitize
```

Import session data from a JSON file or URL.

```bash
$ opencode session import session.json
```

Import into a specific directory.

```bash
$ opencode session import session.json --directory ~/code/project
```

View all subcommands and flags.

```bash
$ opencode session --help
```

## mcp

Manages MCP (Model Context Protocol) servers.

```bash
$ opencode mcp list
```

Start a local MCP server for an external model. It uses the real OpenCode Location runtime and exports its registered tools directly, including plugin and upstream MCP tools normally grouped into CodeMode. Native agent/session permissions still apply. The subagent tool is excluded and cannot be called: this mode does not use an internal model.

```bash
$ opencode mcp serve /path/to/project
```

Call `opencode_context` before working to obtain the selected agent's prompt, global/project instructions, available agents and skills. `opencode_agent` selects another prompt and its permissions without running a model. The native `skill` tool loads skills through OpenCode's normal discovery and permission logic. Context is also available as the `opencode` MCP prompt and `opencode://session/context` resource. Nested `AGENTS.md` instructions discovered by file reads are included in tool responses; `opencode_updates` also retrieves user input and completed background shell jobs.

MCP keeps a durable external Session in its state directory, independent of OAuth tokens and MCP transport IDs. Restarting in the same project restores it; changing the configured directory starts a new Session without deleting the old history. The standalone defaults to `runtime/` beside its env file; the CLI uses its global `mcp-runtime` state directory. Set `OPENCODE_MCP_STATE_DIRECTORY` to isolate another project. Direct calls use OpenCode's native tool lifecycle and TUI/GUI cards: file paths, search patterns, shell commands and output, edit/patch previews, errors and cancellation. They do not create internal model steps or usage records. Older text activity entries remain unchanged.

### Answer questions and permissions in OpenCode

A private native API starts on `http://127.0.0.1:4098` (override with `OPENCODE_MCP_UI_PORT`). Connect the TUI explicitly to this API and open the MCP Session. MCP does not connect to or replace the managed background service; a TUI/GUI attached to another server will not see these requests.

```bash
OPENCODE_PASSWORD="your-native-api-password" opencode --server http://127.0.0.1:4098 /path/to/project
```

Set `OPENCODE_MCP_UI_PASSWORD` to that password, or read the generated URL, password and Session ID from the owner-only `runtime/ui-connection.json`. A GUI supporting custom servers can use that URL, username `opencode` and password. Only expose the OAuth MCP port through your HTTPS tunnel, not the native API. Pending calls wait for an answer or cancellation; disconnecting the MCP client cancels its active requests. Sessions driven externally never wake the built-in model runner, even after background tasks complete or the UI admits new input.

The standalone entry point also accepts `--attach`: it opens that Session in a sibling `opencode` executable (or the CLI on `PATH`) and reads the private connection file automatically.

Use Streamable HTTP when an MCP client must connect over the network. HTTP listens on `127.0.0.1:4096` by default; use `--hostname` and `--port` to change it.

```bash
$ opencode mcp serve /path/to/project --transport http --port 3000
```

### MCP OAuth for ChatGPT

The HTTP server supports a predefined OAuth client using Authorization Code with PKCE (S256). Configure all five `OPENCODE_MCP_OAUTH_*` variables in `packages/cli/.env`; `packages/cli/.env.example` documents them. If any are set but others are missing, the HTTP server refuses to start. Leaving all five unset preserves unauthenticated local development mode. Stdio does not use OAuth.

Set `OPENCODE_MCP_OAUTH_ISSUER` to the public HTTPS origin that forwards to this HTTP server, such as `https://opencode.example.com`, without `/mcp`. Use that same origin for the MCP URL in ChatGPT: `https://opencode.example.com/mcp`. A local `127.0.0.1` URL is only for testing; ChatGPT needs a reachable HTTPS endpoint.

In ChatGPT's MCP server settings, select **OAuth** and copy `OPENCODE_MCP_OAUTH_CLIENT_ID` and `OPENCODE_MCP_OAUTH_CLIENT_SECRET` into **Client ID** and **Client Secret**. Set `OPENCODE_MCP_OAUTH_REDIRECT_URIS` to the exact redirect URI shown there; multiple URIs are comma-separated. The server supports issuer identification and includes `iss` in authorization responses. The example uses ChatGPT's stable callback `https://chatgpt.com/connector_platform_oauth_redirect`.

When linking the connection, enter `OPENCODE_MCP_OAUTH_PASSWORD` on the OpenCode MCP confirmation page. This is a separate MCP access password that you configure, not an OpenCode account, background service password, or OpenAI password. Generate different random values for the client secret and this password. Successful authorization grants the `opencode:tools` scope and access to the exported tools, subject to the selected OpenCode agent's permissions.

For source development, Bun loads `.env` from the CLI directory:

```bash
cd packages/cli
bun run src/index.ts mcp serve /path/to/project --transport http
```

Access tokens expire after one hour. Refresh tokens rotate on use and expire after 30 days. Issued token hashes are saved to a private file and restored on restart. The standalone build stores `oauth-tokens.json` next to its env file; the CLI uses its global state directory. Set `OPENCODE_MCP_OAUTH_TOKEN_FILE` to override the path. Changing the issuer, client ID, client secret, or MCP access password invalidates stored tokens. Pending consent forms and authorization codes are not restored. OAuth credentials are excluded from the environment passed to shell tools and new OpenCode sessions. Local `.env` and `oauth-tokens.json` files are ignored by Git; commit only `.env.example`.

See the [OpenAI authentication guide](https://developers.openai.com/apps-sdk/build/auth) for ChatGPT's OAuth requirements.

Add a remote server.

```bash
$ opencode mcp add context7 --url https://mcp.context7.com/mcp
```

Add a local server to the global config.

```bash
$ opencode mcp add everything --global -- npx -y @modelcontextprotocol/server-everything
```

Add a local server with an environment variable.

```bash
$ opencode mcp add everything --env LOG_LEVEL=debug -- npx -y @modelcontextprotocol/server-everything
```

Add a remote server with a header.

```bash
$ opencode mcp add context7 --url https://mcp.context7.com/mcp --header CONTEXT7_API_KEY=secret
```

Authenticate with an OAuth-capable remote server.

```bash
$ opencode mcp auth sentry
```

Remove stored OAuth credentials for a server.

```bash
$ opencode mcp logout sentry
```

View all subcommands and flags.

```bash
$ opencode mcp --help
```

## pair

Prints one-time links, plus a QR code of the first one, that sign a browser or
app in to the server. Links expire after 5 minutes and work once.

```bash
$ opencode pair
```

Use an external URL in the links.

```bash
$ opencode pair --url https://dev.example.com
```

Pair from anywhere through an OpenTunnel remote address. This exposes the
server to the internet, so the first time it enables remote access it explains
this and asks you to accept. See [Remote access](/cli/web#remote-access).

```bash
$ opencode pair --remote
```

Accept without a prompt, for example in a script without a terminal.

```bash
$ opencode pair --remote --yes
```

View all subcommands and flags.

```bash
$ opencode pair --help
```

```bash

```


```bash

```

```bash

```

```bash
$ opencode service get hostname
```

```bash
$ opencode service set hostname 0.0.0.0
```

```bash
$ opencode service set cors https://app.example.com
```

Pass an environment variable to the server process.

```bash
$ opencode service set env OPENCODE_LOG_LEVEL DEBUG
```

Reset a setting to its default.

```bash
$ opencode service unset hostname
```

View all subcommands and flags.

```bash
$ opencode service --help
```

## reload

Reloads configuration without restarting the server. Running sessions continue with fresh services at the next step boundary.

```bash
$ opencode reload
```

## uninstall

Stops background services, removes the global cache, and uninstalls OpenCode. Session data, configuration, and
state are not removed.

```bash
$ opencode uninstall
```

Preview what would be removed.

```bash
$ opencode uninstall --dry-run
```

View all subcommands and flags.

```bash
$ opencode uninstall --help
```
