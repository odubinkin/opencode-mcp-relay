# Настройка MCP Relay в OpenCode (форк)

Эта инструкция относится к форку [odubinkin/opencode-mcp-relay](https://github.com/odubinkin/opencode-mcp-relay), а не к стандартной сборке OpenCode upstream.

MCP Relay позволяет внешнему MCP-клиенту (в том числе ChatGPT) использовать **нативные инструменты OpenCode** в выделенной сессии. Внутренняя LLM для этих вызовов не запускается. При этом сохраняются существующие разрешения OpenCode: запросы подтверждения, вопросы и действия инструментов видны в TUI и GUI.

## Начало работы

1. Откройте проект в OpenCode Relay.
2. Вызовите `/connect` → **MCP Relay Mode** для настройки. Команда `/mcprelaymode` (коротко `/relay`) открывает настройку при первом запуске, а затем запускает или открывает сессию Relay.
3. Выберите **один** режим подключения:
   - **OpenAI Tunnel · private, no password** — предпочтителен для ChatGPT, если в вашей организации OpenAI доступна функция Secure MCP Tunnel. Не нужен публичный URL или `cloudflared`.
   - **Public HTTPS · OAuth password** — для внешних MCP-клиентов, которым нужен прямой публичный HTTPS MCP endpoint, с отдельным паролем на OAuth-странице.

Ненужные поля в GUI скрываются. В TUI выбор доступен в разделе **Connection mode**, настройки активного режима отображаются в соответствующих пунктах. Изменения вступают в силу только после сохранения и, если Relay уже работает, перезапуска.

## Вариант A: OpenAI Secure MCP Tunnel

### Что потребуется

- Доступ к OpenAI Platform с функцией Secure MCP Tunnel и правами управлять туннелем.
- Созданный туннель с ID вида `tunnel_...`, связанный с необходимым рабочим пространством ChatGPT.
- API-ключ OpenAI с необходимыми правами на чтение и использование туннеля (**Tunnels Read + Use**). Доступность функции и названия элементов интерфейса зависят от настроек OpenAI.

**Как настроить**

1. Создайте Secure MCP Tunnel в [настройках OpenAI Platform](https://platform.openai.com/settings) и свяжите его с нужным ChatGPT workspace.
2. Выберите в OpenCode Relay **OpenAI Tunnel · private, no password**.
3. Укажите **OpenAI Secure MCP Tunnel ID** и **OpenAI API key**.
4. Нажмите **Save and start Relay**. Если изменяете запущенный Relay, сохранение должно перезапустить текущий listener.
5. В ChatGPT добавьте собственный MCP-сервер с типом подключения **Tunnel** и выберите/введите тот же Tunnel ID.
6. В ChatGPT обновите инструменты MCP и попробуйте безопасное действие, например чтение файла в тестовом проекте. Проверяйте карточки вызовов и запросы разрешений в OpenCode.

OpenCode сам подключается к OpenAI по исходящему HTTPS. Отдельный `tunnel-client`, `cloudflared`, публичный домен, callback URL и OAuth-страница Relay не нужны. Локальный MCP listener доступен только на `127.0.0.1` (по умолчанию порт `4099`).

### Где проверяется пароль?

В этом режиме **пароль Relay не запрашивается и не проверяется**. API-ключ используется серверной частью OpenCode для подключения к API OpenAI. Доступ ChatGPT к туннелю определяется разрешениями туннеля / рабочего пространства на стороне OpenAI; запуск инструмента дополнительно ограничивается системой разрешений OpenCode.

Это **не эквивалент второго пользовательского фактора аутентификации**. Если требуется, чтобы каждый новый клиент вводил самостоятельный пароль перед доступом к инструментам, используйте режим **Public HTTPS · OAuth password**. Другой локальный процесс на этом же компьютере потенциально может обратиться к loopback MCP listener напрямую, поэтому не давайте недоверенным локальным процессам доступ к компьютеру и **не публикуйте порт 4099 наружу**.

Туннельный режим в форке проверен на локальном имитаторе API OpenAI и не подтверждён сквозным тестом с реальной учётной записью ChatGPT; совместимость и доступность функции следует проверить с собственным Tunnel ID.

## Вариант B: Public HTTPS + OAuth

Режим оставлен для совместимости и клиентов, не использующих OpenAI Tunnel. Здесь **Access password** — пароль, который пользователь вводит в браузере на странице авторизации Relay, чтобы MCP-клиент получил OAuth access/refresh tokens. Он отличается от **OAuth client secret** (секрет приложения-клиента) и от пароля macOS/OpenCode.

1. Выберите **Public HTTPS · OAuth password**.
2. В поле **Public URL (origin without /mcp)** укажите публичный HTTPS origin, например `https://relay.example.com` (без завершающего пути `/mcp`).
3. **Listen hostname** — адрес локального интерфейса (обычно `127.0.0.1`), **Listen port** — обычно `4099`.
4. Настройте собственный reverse proxy или внешний HTTPS-туннель так, чтобы **весь origin**, включая `/.well-known/*`, `/oauth/*` и `/mcp`, проксировался на указанный локальный listener.
5. Укажите **Callback URLs** — точный OAuth redirect URL из настроек подключаемого клиента.
6. Укажите **OAuth client ID** (по умолчанию `opencode-relay`), сохраните или сгенерируйте **OAuth client secret** и **Access password**. Пустые секреты при первом сохранении генерируются автоматически, при последующих — сохраняют прежние.
7. Сохраните настройки и запустите Relay. Скопируйте параметры подключения из раздела **Connection**.
8. В MCP-клиенте настройте OAuth с параметрами:

| Параметр | Значение |
| --- | --- |
| MCP URL / Resource | `https://relay.example.com/mcp` |
| Authorization URL | `https://relay.example.com/oauth/authorize` |
| Token URL | `https://relay.example.com/oauth/token` |
| Client ID / secret | Значения из настроек Relay |
| Token endpoint authentication | `client_secret_post` |
| Scope | `opencode:tools` |
| PKCE | `S256` |

OIDC и dynamic client registration в Relay не реализованы. В OAuth-окне введите **Access password**. Выданные access/refresh токены дают доступ в пределах срока действия и проверяются Relay при обращении к `/mcp`.

Пароль OAuth нужен именно для пользовательского подтверждения выдачи токенов через публичный endpoint. Для приватного OpenAI Tunnel он не используется — это принципиальное, а не косметическое отличие двух режимов.

## Управление, хранение и восстановление

- **Save settings** сохраняет настройки, но не открывает listener. **Save and start Relay** сохраняет и запускает; при изменении работающего Relay используйте перезапуск.
- **Stop Relay** или закрытие вкладки его сессии останавливает listener. Переключение на другую вкладку не останавливает релей.
- При открытии существующей MCP-relay-сессии, включая восстановленную после запуска приложения, клиент автоматически попытается запустить Relay, если сохранённая конфигурация позволяет.
- Настройки без секретов находятся в **глобальном** конфиге OpenCode (`mcpRelay`), а OpenAI API key, OAuth client secret и Access password — в штатном **Credential store**. Не записывайте их в git или локальный `.env`.
- Привязка Relay к сессии и хеши действующих OAuth-токенов сохраняются в существующей базе данных OpenCode. История сессии переживает перезапуск.
- Переключение режима не удаляет ранее сохранённые секреты; оно меняет, **какой механизм аутентификации используется**. При переходе на Public HTTPS старые OAuth-параметры можно переиспользовать или заменить.

## Инструменты и диагностика

Сессия Relay показывает запросы разрешений, вопросы, команды и изменения файлов в обычном OpenCode UI. Внешняя модель должна передавать для нативных MCP-вызовов аргумент `_opencode_summary` — краткое объяснение действия на языке пользователя (1–240 символов). Это объяснение отображается до запуска инструмента. Субагенты в режиме Relay отключены.

Если запуск не удаётся, проверьте настройки активного режима и сообщения об ошибках в диалоге. Для OpenAI Tunnel: ID, разрешения API-ключа, привязку к ChatGPT workspace и исходящий HTTPS-доступ к `api.openai.com`. Для Public HTTPS: сертификат, точные callback URLs, маршруты reverse proxy, client ID/secret и ввод Access password. Если Relay уже работает в другой директории, сначала остановите его: смена UI-вкладки не перенаправляет активное подключение модели на другой проект.

## Локальная сборка macOS

Рядом с графическим приложением `OpenCode Relay.app` распространяются `opencode` и `start.command` для запуска TUI. Запускайте `start.command` из директории нужного проекта; скрипт сохраняет текущий рабочий каталог. Сборка форка должна содержать CLI, собранный из **этих же исходников**, иначе графическое приложение может подключиться к backend без нужных функций Relay.
